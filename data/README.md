# P16 — Data dictionary + known quirks

## The sales file — `data/raw/daily_sales_SAMPLE.csv`

SAMPLE daily sales file for the fictional shop **DailyNeeds Mart,
Lahore**, Mon 2026-09-07 → Sun 2026-11-01 (8 full weeks, 56 days).
295 lines, PKR 570,445 total. Generated by `src/generate_data.py`
(seed 20261112) from 25 fixed-price products in 6 categories, with
4–7 lines a day, a weekend lift (Fri–Sun lines average 36.0% more
units) and ~2% weekly growth baked in — so the automation has a
real trend and a real weekend pattern to surface.

| Column | Type | Meaning |
|---|---|---|
| date | text | `yyyy-mm-dd`; the sale day — must fall inside its week |
| week_no | integer | 1–8; Monday-start weeks, 1 = 2026-09-07 |
| week_start | text | The Monday of the sale's week (`yyyy-mm-dd`) — the report's key |
| product | text | One of 25 products; price is fixed per product |
| category | text | One of 6: Groceries, Dairy, Bakery, Household, Beverages, Personal Care |
| qty | integer | Units sold on the line; always > 0 |
| unit_price_pkr | integer (PKR) | Fixed per product (e.g. Desi Ghee 1kg = 1,450) |
| amount_pkr | integer (PKR) | Always exactly qty × unit_price_pkr — checked as code |

## The weekly summary — `data/processed/weekly_summary.csv`

One row per week (8 rows), produced by `src/analyze.py` from the
raw file — the same table the Apps Script reproduces in Sheets with
SUMIFS and the SQL in `sql/weekly_aggregation.sql` reproduces in
SQLite. Columns: week_no, week_start, lines, qty, total_pkr,
wow_growth_pct (blank for week 1), top_category, then one
`<category>_pkr` column per category. The six category columns sum
to total_pkr on every row — checked as code.

## Known quirks

- **Week 5 is a spike, not a trend break.** Week 5 (from
  2026-10-05) totals PKR 86,875, +30.94% on week 4 — the seeded
  generator's noise, not a planted event. The report shows it
  honestly as the best week; no cause is claimed.
- **Growth is modest.** Week 1 → week 8 is only +4.12% despite the
  +2%/week growth baked into the generator, because weekly noise
  (±5 lines a day) swamps the trend at this size. The script reports
  the measured growth, never the planted one.
- **The .db is not uploaded.** `data/processed/sales.db` is
  rebuildable from `src/build_sqlite.py` + the raw CSV, so it stays
  out of the repo — same rule as every other project here.
